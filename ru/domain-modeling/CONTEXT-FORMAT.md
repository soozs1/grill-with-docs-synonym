# Формат CONTEXT.md

## Структура

```md
# {Имя контекста}

{Одно-два предложения: что это за контекст и зачем он существует.}

## Язык

**Order / Заказ**: {Одно-два предложения: что это есть}
_Avoid_: Purchase, transaction, покупка

**Invoice / Счёт**: Запрос на оплату, отправляемый клиенту после доставки.
_Avoid_: Bill, payment request

**Customer / Клиент**: Физическое или юридическое лицо, размещающее заказы.
_Avoid_: Client, buyer, account, покупатель
```

## Правила

- **Различай полные и частичные синонимы.** Полные синонимы (взаимозаменяемы в любом сценарии: ревью / review) пиши со-канонически через `/` с пробелами. Частичные (расходятся в каком-то сценарии: клиент / покупатель) — один в канон, остальные в `_Avoid_`.
- **Для кодо-связанных концептов — английский первым.** Если термин мапится в код (класс, функция, таблица, файл), первый вариант в каноне — английский/латинский: `Order / Заказ`. Это сигнал, а не ограничение; явного поля «форма для кода» нет.
- **Будь категоричен.** Фиксируй канон — один термин или набор полных синонимов через `/` — а всё лишнее выноси в `_Avoid_`.
- **Держи определения короткими.** Максимум одно-два предложения. Определяй, что это ЕСТЬ, а не что оно делает. Определение — на рабочем языке команды.
- **Включай только термины, специфичные для контекста этого проекта.** Общие программистские концепты (таймауты, типы ошибок, утилитарные паттерны) сюда не относятся, даже если проект активно их использует. Прежде чем добавить термин, спроси: это понятие уникально для данного контекста или это общий программистский концепт? Глоссарию принадлежит только первое.
- **Группируй термины под подзаголовками**, когда вырисовываются естественные кластеры. Если все термины относятся к одной связной области, плоский список нормален.

## Одно- и многоконтекстные репозитории

**Один контекст (большинство репозиториев):** один `CONTEXT.md` в корне репозитория.

**Несколько контекстов:** `CONTEXT-MAP.md` в корне перечисляет контексты, где они живут и как связаны друг с другом:

```md
# Карта контекстов

## Контексты

- [Ordering](./src/ordering/CONTEXT.md) — принимает и отслеживает заказы клиентов
- [Billing](./src/billing/CONTEXT.md) — выставляет счета и обрабатывает платежи
- [Fulfillment](./src/fulfillment/CONTEXT.md) — управляет сборкой и отгрузкой со склада

## Связи

- **Ordering → Fulfillment**: Ordering публикует события `OrderPlaced`; Fulfillment потребляет их, чтобы начать сборку
- **Fulfillment → Billing**: Fulfillment публикует события `ShipmentDispatched`; Billing потребляет их, чтобы выставить счёт
- **Ordering ↔ Billing**: Общие типы для `CustomerId` и `Money`
```

Скилл сам определяет, какая структура применима:

- Если есть `CONTEXT-MAP.md` — читает его, чтобы найти контексты
- Если есть только корневой `CONTEXT.md` — один контекст
- Если нет ни того, ни другого — создаёт корневой `CONTEXT.md` лениво, когда будет зафиксирован первый термин

Когда контекстов несколько, определи, к какому относится текущая тема. Если неясно — спроси.
